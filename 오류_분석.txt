# Next.js on Cloudflare Pages 404 오류 분석

현재 겪고 계신 문제에 대한 상세 분석 및 해결 과정입니다.

## 1. 현상

- GitHub Actions를 통한 빌드 및 Cloudflare Pages 배포는 성공적으로 완료됩니다.
- 하지만 배포된 URL (`https://feature-phase1-4-implementat.pbr.pages.dev/login`)에 접속하면 `404 Not Found` 오류가 발생합니다.
- 이는 Next.js 앱의 정적 파일이 아닌, 서버에서 렌더링되어야 하는 동적 페이지가 올바르게 제공되지 않고 있음을 의미합니다.

## 2. 근본 원인

Cloudflare Pages가 동적 페이지 요청(예: `/login`)을 처리해야 할 **`_worker.js` 함수로 전달하지 않고**, 해당 경로에 일치하는 정적 HTML 파일(예: `/login.html`)을 찾으려 하기 때문입니다. 동적 앱에서는 이런 정적 파일이 존재하지 않으므로 404 오류를 반환합니다.

이 문제의 핵심은 `open-next` 라이브러리가 생성한 빌드 결과물과, 이를 배포하는 Cloudflare Pages 플랫폼 간의 **라우팅(Routing) 설정이 완벽하게 일치하지 않기 때문**입니다.

## 3. 시도된 해결 방법 및 분석

### 시도 1: `wrangler.toml` 설정 최적화
- **내용:** Cloudflare Pages 프로젝트에 맞게 `wrangler.toml` 파일을 수정했습니다. (`pages_build_output_dir` 추가 등)
- **결과:** 배포 과정의 경고는 해결되었으나, 404 문제는 해결되지 않았습니다. 이는 배포 설정의 문제라기보다는 라우팅 문제임을 시사했습니다.

### 시도 2: 미들웨어 로직 수정
- **내용:** `src/middleware.ts`가 특정 경로를 잘못된 페이지로 재작성(rewrite)할 가능성을 염두에 두고, `/login`, `/admin` 등 핵심 경로를 테넌트 확인 로직에서 제외했습니다.
- **결과:** 로직 자체는 수정되었으나, 404 문제는 여전했습니다. 이는 라우팅 문제로 인해 미들웨어 함수 자체가 해당 경로에서 실행조차 되지 않았을 가능성을 보여줍니다.

### 시도 3: 빌드 시점 오류 해결 (D1 바인딩, 인증 로직)
- **내용:** `next build` 과정에서 발생하던 D1 바인딩 및 인증 옵션(authOptions) 관련 오류를 해결했습니다. 이를 위해 런타임과 빌드타임의 환경 차이를 인지하고, D1 클라이언트를 동적으로 초기화하도록 코드를 대대적으로 리팩토링했습니다.
- **결과:** **이 수정 덕분에 빌드 및 배포가 성공적으로 완료될 수 있었습니다.** 하지만, 이는 빌드 프로세스를 정상화했을 뿐, 근본적인 런타임 라우팅 문제를 해결하지는 못했습니다.

### 시도 4: `_routes.json` 파일 생성 (가장 핵심적인 시도)
- **내용:** Cloudflare Pages의 라우팅 동작을 명시적으로 제어하기 위해 `_routes.json` 파일을 빌드 결과물(`.open-next` 디렉토리)에 포함시켰습니다. 이 파일은 모든 동적 요청을 `_worker.js` 함수로 보내도록 지시하는 역할을 합니다.
- **결과:** **실패했습니다.** 이것이 가장 유력한 해결책이었음에도 실패한 이유는 다음과 같이 추정됩니다.
    1.  `cloudflare/pages-action@v1` 액션이 `.open-next` 디렉토리 내부의 `_routes.json`을 올바르게 인식하지 못했을 수 있습니다. Pages는 보통 프로젝트의 최상위 루트 디렉토리에서 이 파일을 찾습니다.
    2.  `_routes.json` 파일의 내용에 문제가 있었을 수 있습니다.
    3.  Cloudflare Pages 프로젝트의 대시보드에 설정된 다른 규칙(리디렉션 등)과 충돌했을 수 있습니다.

## 4. 다음 단계 제안

가장 유력한 원인은 **`_routes.json` 파일의 위치**입니다. `pages-action`이 `.open-next` 디렉토리를 배포하면서 그 안의 `_routes.json`을 루트 설정 파일로 인식하지 못하는 것으로 보입니다.

**해결책 제안:** `.open-next` 디렉토리 안에 `_routes.json`을 생성하는 대신, **프로젝트의 최상위 루트에 `_routes.json` 파일을 직접 생성**하여 Cloudflare Pages가 이를 명확하게 인식하도록 해야 합니다.
